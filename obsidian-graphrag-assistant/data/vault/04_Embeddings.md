# Embeddings

Embeddings are dense numerical vector representations of text. They are generated by neural networks trained to map semantically similar text to nearby points in a high-dimensional vector space.

## What Embeddings Capture

Unlike keyword-based representations, embeddings capture semantic meaning. Two sentences can have completely different words but similar embeddings if they convey similar meaning:

- "How do I implement RAG?" 
- "What are the steps to build retrieval augmented generation?"

These would have high cosine similarity even with no shared keywords.

## How Embeddings Are Generated

In this project, embeddings are generated using the Gemini embedding model (`gemini-embedding-001`). The model accepts a text string and returns a vector of 768 dimensions.

## Embedding Dimensionality

The number of dimensions affects both quality and storage cost. Common choices are:
- 768 — Used in this project (BERT-style, balanced)
- 1536 — Higher quality, more storage
- 3072 — Highest quality, significant storage

All embeddings in a given vector index must have the same dimensionality.

## Role in RAG

Embeddings are the core mechanism that enables [[Semantic_Search]]:

1. Documents are chunked and each chunk is embedded
2. Embeddings are stored in a [[Vector_Database]]
3. At query time, the question is embedded using the same model
4. [[Vector_Search]] finds chunks with similar embeddings

## Role in GraphRAG

In [[GraphRAG]], embeddings are also stored on [[Neo4j]] nodes. The vector search identifies entry points into the knowledge graph, after which [[Knowledge_Graph]] traversal expands the context.
